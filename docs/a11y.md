# Accessibility checklist

Target: **WCAG 2.2 AA**, plus 44 × 44 px tap targets. Run this list before every launch and after any UI
change. The audit for issue #54 (2026-11-16) passed every item below.

## Automated

- [ ] **axe-core, tags `wcag2a wcag2aa wcag21a wcag21aa wcag22aa`: zero violations on every route.**
  Routes: `/`, `/products`, all six `/products/<slug>`, `/about`, `/blog`, one post, one
  `/blog/category/<id>`, `/contact`, `/privacy`, `/terms`, `/waitlist/confirm` and the 404 page. Force
  scroll-reveal content visible first (`[data-reveal]{opacity:1;transform:none}`) so contrast checks see
  the final colours. CI runs this on every pull request (`e2e/a11y.spec.ts`, desktop and phone).
- [ ] `npm run lint` (eslint-plugin-jsx-a11y rules through eslint-config-next) has no warnings.

## Structure

- [ ] **Skip link.** The first Tab on any page shows "Skip to content"; Enter moves focus to `main#main`.
- [ ] **Landmarks.** One `header`, one `main#main`, one `footer`. Every `nav` has a label ("Main",
  "Footer", "On this page", "Blog categories", "Suggested pages").
- [ ] **Headings.** Exactly one `h1` per page, with no skipped levels. Blog posts reject `#` headings at build
  time.
- [ ] **Page changes.** After a page transition, focus moves to the new `h1` and the route is announced.

## Keyboard and focus

- [ ] No positive `tabindex`; focus follows the reading order.
- [ ] Every focusable element shows a ring: violet-500 on light surfaces, violet-300 on dark. Stretched-link
  cards outline the whole card; form fields use a 2 px ring.
- [ ] No focus ring is clipped by a scrolling parent (check the chip rows at 390 px).
- [ ] Menus, accordions, the products filter, the blog filter and "Show more" all work with Tab, Enter and
  Space. The mobile menu traps focus and closes with Escape.

## Forms

- [ ] Every field has a visible `<label>`. Errors appear under the field, are tied with `aria-describedby`,
  and set `aria-invalid`. Focus moves to the first invalid field.
- [ ] A live region announces every state: error count, sending, sent, failed.
- [ ] Colour is never the only signal: errors have an icon and text, and invalid fields a thicker ring.

## Colour and text

- [ ] Body text at least 4.5:1, large text and UI parts at least 3:1, including mockup captions and dimmed
  stepper steps. Kinly's page (`readability: "large"`) uses full-strength text, at least 16:1.
- [ ] Text reflows at 320 px wide (WCAG 1.4.10: 400% zoom of a 1280 px window) without horizontal scrolling.

## Motion (`prefers-reduced-motion: reduce`)

| Effect | Expected |
|---|---|
| Lenis smooth scroll | Off |
| Page transition panels; back/forward cross-fade | Skipped |
| Scroll reveals, filter re-flow, headline and statement effects, stepper scrub | Opacity at most, no movement |
| Typed word, digit roller | Static |
| WebGL star field and footer smoke | Static fallback, no animation loop |
| Ticker, button and blog-card hover effects | Off |
| Hover lifts and icon tilts | Off |
| Any CSS transition or keyframe | Instant (global rule) |

Check in Chrome DevTools: Rendering, then "Emulate CSS media feature prefers-reduced-motion: reduce".

## Touch

- [ ] Every interactive target is at least 44 × 44 px at 390 px wide. Exceptions: links inside running text,
  and card titles whose `::after` covers the whole card.

## Screen readers (manual, before launch)

- [ ] VoiceOver (Safari, iOS) and NVDA (Firefox, Windows): read Home, a product page, a post, and send the
  contact and waitlist forms with an error and then successfully.
